## 4. C cell 崩溃事故(已修复)

- **现象**:C-smart/naive/naive_alloc/smart_sync 各跑 4.5-5.5 分钟即退,但 run_all.py 结尾横幅「全部完成」无条件打印,链条完成检查被假横幅骗过、把崩溃记成正常完成。
- **根因**:mixed 空间含 hybrid 大模型(TemporalEventGNNJODIE),其 forward 必须有外部 `graph_ctx`;serial 路径有 `graph_ctx = None if model_name=="jodie_rnn" else graph_template`(trainer.py:200),pipeline 的「方案 C」全数据评估分支(evaluate_arch_pipeline)漏传。rnn_only 的 B/D/E/F 全是 jodie_rnn,此 bug 从未触发。
- **修复**:trainer.py evaluate_arch_pipeline 增加 `graph_template` 参数并传给 evaluate_ranking_metrics(与 serial 同规则);chain_all.sh 完成判定改为「全部完成 且 无『失败策略:』行」,run 结束遇失败策略行即中止链条。崩溃 log 留档 `*_crashed_HHMM.log`。
- **验证**:重跑 C-smart 已越过原崩溃点(batch1 → batch2 正常推进)。

## 6. 2026-09-12 重大发现:五臂链 D/F/C 的 "smart" 臂跑成了同步重复

- **根因**:run_all.py:243 `SMART_PIPELINE_MODE = "naive"`(五臂链实施时翻转的默认值),而 configs.py `_STRATEGY_CONFIGS` 的 `D_smart/F_smart/C_smart` 未显式设 `SMART_PIPELINE_MODE` → 三臂全部继承 naive(同步批驱动),与 smart_sync **配置完全相同**。
- **证据**:F-smart 的 config.json 快照 `SMART_PIPELINE_MODE='naive'`;F-smart 7.5 t/h ≈ F-smart_sync 7.4 t/h(行为重复);C-smart 崩溃在同步循环(trainer.py:920);D-smart rerun 与 D-smart_sync 同配置却慢 3.2×(3.21h vs 1.00h)= **纯机器争用,不是策略差异**。
- **真异步 smart 只有 B-smart(09-07)和 E-smart(09-09 午前,翻转前)**,timing_log mode=`pipeline_smart` 可证。
- **对判读的修正**:
  - D cell「naive 反超 smart」(9.5 vs 4.0 t/h)是污染假象——干净的同配置 run(smart_sync)14.6 t/h > naive。**0/4 cell 反超**(B 0.85 / D 作废→用 14.6 判输 / E 0.86 / F 0.95)。
  - naive vs DP(修复后)**全胜**:2.19 / 1.13 / 1.13 / 2.48——Phase 1「naive/DP 未反超(0.93)」是 buggy DP 假数字。
  - smart_sync 四个 cell 全第一(45.5/14.6/11.0/7.4 t/h):同步架构并行 = 吞吐上界,pipeline 从未赢过。
  - C3 归因(B/E 干净异步对照):async 比 sync 慢 18%(B)/ 5%(E)→ 异步不贡献速度,3.0× 不能归给异步引擎。
  - 分配探针:D 兑现(+28%)/ F 不兑现(-14%)。
  - 真趋势:naive 绝对加速比 vs serial = 0.89→1.32→1.56→1.90 单调;naive/smart_sync 比值 B 0.70→F 0.97(200K 追平)。
- **处置**:链中不杀、不改配置(铁律)。当前 C-smart 跑完留作与 C-smart_sync 的重复校验对(同 F 的两份 sync 1.91/1.93)。链结束后补跑三臂真异步 D/F/C-smart(先改 `_STRATEGY_CONFIGS` 加 `SMART_PIPELINE_MODE="smart"`),预计 ~6h;D-smart 的 3.21h 降级为「同配置争用对照」,不得当 smart 臂使用。

### 7.2 已锁定结论(补跑/G 出数不会改变)

1. **同步架构并行(smart_sync)是全部 5 个已完成 cell 的吞吐第一**(45.5/14.6/11.0/7.4/70.5 t/h);pipeline 从未赢过它,比值 0.65-0.97。
2. **naive 对 DP 吞吐全胜**(1.06-2.48×)——Phase 1「未反超 DP」确系 buggy DP 假数字;**但 DP 保真只在小负载(20K)成立**,100K/200K/mixed 全部分叉且 test 方向不稳定。两句话必须分开写。
3. **naive/serial 随「stage 重量」单调上升**(rnn_only 0.89→1.32→1.56→1.90;C mixed 同数据量直接 1.54)——数据大或模型大都帮 pipeline,是论文可用的主趋势。
4. **异步引擎不贡献吞吐**(B async 比 sync 慢 18%,E 慢 5%)。D/F/C 补跑只影响幅度;除非出现意外反转(低概率),方向已定。
5. **分配探针 1/3 兑现**(D +28%;F、C -14%)——不利结果照报,「前重后轻」不成规律。
6. **保真格局**:同步族五 cell 全部内部位级一致;DP 分叉规律见 §2;12t 无 rerank 的 D/E serial 噪声大(选 8.9K 小模型),不作为判据。
