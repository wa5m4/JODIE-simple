| 条目 | 内容 |
|---|---|
| **系统贡献** | **PipeTGL:面向 TGNN 的 pipeline 型 NAS 系统**。REINFORCE 控制器搜 JODIE 家族空间(聚合函数、时间衰减、记忆单元、时间投影),候选经**流水线执行器**评估;serial / 数据并行 / 架构并行三个 baseline 走**同一搜索框架**(同控制器、同空间、同 trial 数),执行策略是唯一变量,对比天然公平。**保真执行为内建设计属性**(Challenge I):并行训练尊重流的 RAW 依赖;随机状态协议(per-trial 种子纪律、RNG 保留的状态迁移、off-policy 控制器更新)让每个后端**按构造**复现 serial 选择——不是碰巧,是协议保证。 |
| **技术贡献1:流水线策略** | **按分区成本均衡切阶段,阶段边界保 RAW 语义**(阶段内时序保序、阶段间状态交接),无逐候选 profiling 开销——直指 Challenge II:实测分区倾斜 new users 每分区 **1.83×(20K)→ 4.09×(100K)→ 114.5×(411K)** 而事件数严格均匀,静态分配必然 idle + straggler。**证据**:恒胜数据并行 baseline(1.06–2.48×);随负载增大**逼近**架构并行 baseline(0.65→0.99,重负载收敛到其水平);分配探针 2×[2,1] vs 3×[1,1,1] 仅 **1/3 兑现**(D +29%,F/C −14%)——粗调静态分配无普适增益,**正是引入异步引擎的动机**。保真:同步族所有 cell 族内位级一致(5 策略互证)。 |
| **技术贡献2:异步生成引擎(Challenge III)** | **pipeline 独有的结构**:持久 worker 池 + 候选生成与训练重叠 + off-policy 批量 RL(采样时 logprob 重算,更新不阻塞池)——GPU 几乎不空转。**证据**:对同步流水线**普适增益 +21~98%**(数据越小放大越狠:B +98% / D +77% / F +21% / G +26%);**异步流水线反超架构并行 baseline 1.15–1.38×**(B/D/F/G 全线);对 serial baseline 至 **2.3×**(D 2.32× / F 2.31×)。引擎为流水线的连续流结构而设计。机制:同步批循环「采样→整批评估→更新」的串行结构留下批间生成停摆,持久池把生成移出关键路径。 |
| **实验贡献** | **在 MOOC 数据集的七配置上进行了大量实验**(20K–200K 交互 × 2–3 卡 × rnn_only/mixed,50+rerank8 与 12 trial,预注册判据),**验证了流水线策略与异步生成引擎的有效性**。**与三种自然并行化 baseline 对比**:恒胜数据并行(1.06–2.48×)、异步流水线反超架构并行(1.15–1.38×)、**至 2.3× 加速于串行 baseline,同时不影响准确率**——异步流水线在全部 4 个已测 cell 选出与 serial **位级一致**的架构(B/D/F/G:133888 / 8896 / 133888 / 338240)。 |
